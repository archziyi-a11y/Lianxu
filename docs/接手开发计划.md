# Lianxu 接手开发计划

日期：2026-10-24。状态：第一至第四阶段已完成；第五阶段前插入动态档案与分析方法实施，第五阶段待实施。工程基座提交：`cecccd1`。

## 目标与依据

在现有Android Studio基座上完成首版，不重新发明产品结构。产品依据为[统一规格](../specs/当前规格/README.md)，本计划规定实施顺序，不修改已确认的产品范围。旧.agent/plan.md及外部完成汇总只作历史记录。

保留HorizontalPager双页、位置标记、六列跨度网格及收发动效的可用部分；更换硬编码指标、随机回复、仅按标题修改数值的协议，以及未持久化的业务状态。

首个可验证目标：填写资料与目标 → 获得营养和餐食建议 → 多卡补充文字／图片 → 保存记录并计算 → 组织更新后的看板 → 重启后继续。先有本地真实业务往返，再接通真实模型，不把演示模式做成另一套产品。

## 现状基线

现有资料、目标和体重有基础存取，营养公式有初步实现；训练、摄入、轮次及看板等虽声明实体，尚未接入业务。卡片目前是内存中的固定示例，图片未进入API请求，异常分支清空批注。现有模板测试不足以证明业务完成。

已有APK不代表当前源码已独立通过构建和模拟器验收。接手后先复现构建与运行结果，记录工具链及模拟器，不沿用外部未经复核的通过声明。

## 第一阶段：稳定基座与共享数据

工作：

- 复现构建，确认实际依赖和SDK；记录并锁定动态依赖版本，避免同时进行无关技术栈升级。
- 修复输入失败被清空、未知体重填零、目标阶段重叠等已知问题。禁止请求日志输出密钥与完整个人材料，完善密钥存储及备份排除。
- 接通档案、测量、训练、摄入、有效认识的Repository；补齐输入附件、草稿、轮次、任务、看板、快照、计算和助手产物的实际存取。
- 增加数据库schema导出与后续迁移路径，保留已有资料。附件复制到应用私有存储，不能依赖临时URI长期有效。
- 明确五类对象的唯一归属；卡片仅保存引用、排布和有版本的渲染缓存。

通过条件：填写或更正资料后两页读到相同对象；保存粗略训练及图片后杀进程仍可恢复；未知字段不填零；目标切换只有一个有效阶段；事务失败不留下半批记录。

## 第二阶段：真实计算、餐食与动态看板

工作：

- 将现有公式拆成可测试的计算接口，支持指定日期、完整精度、缺参结果、手动目标和版本化计算依据；舍入仅在展示发生。
- 将规格包中的31食物／36配方条目导入应用资产，验证来源、状态、单位与引用。接通食物总量、摄入去重、餐食候选与替换、训练摘要及体重趋势。
- 实现当日规划与各餐持久对象；无需实际摄入也能生成规划，摄入补充后能计算并调整剩余餐食。
- 将DashboardCard(title,value)替换为规格中的组件和卡片结构。支持文本、图片、指标、清单、选择与趋势的同卡组合；数值绑定Calculation，文字建议绑定助手产物。
- 去除无来源的心率、步数等初始业务值。用实际资料建立初始看板，信息不足时展示可用内容及补充入口。

通过条件：规格数值夹具、未知值、总量防双计及份量换算用例通过；同一份资料生成可追溯的营养和餐食建议；更正资料使受影响结果过期并重算；替换一餐不改已摄入快照。

## 第三阶段：完整组件协作与真实AI

工作：

- 多卡批注冻结成一个InputBundle和Turn，保留原话、图片、cardId、revision与当时内容快照；发送重试沿用submissionId。
- 实现结构化上下文生成和受约束工具：读取记录、查食物、计算、暂存及finish_proposal。按整轮要求理解关联，不将批注目标机械地当作唯一可修改对象。
- 验证对象版本、来源引用、计算绑定、作用范围及用户保留项；业务变更、分析、卡片、轮次与凭据同事务提交。失败保留旧结果与本轮输入。
- 接通可配置的DeepSeek适配器，先核对供应商当前模型及多模态格式；图片内容实际送达，支持多步工具往返，设置超时与有限重试。
- 本地协议夹具使用固定、可解释结果验证流程，明确标注演示；去除随机改数。真实服务与演示复用同一校验、计算和提交路径。
- 使用已有意图表达指导目录，不固化业务卡模板；允许新增解释、选择项及相关卡片调整。

通过条件：多卡补充共同影响剩余饮食；图片参与真实理解；模型不能用展示字符串绕过计算或改写历史实绩；故意制造版本冲突与非法引用时整批不应用；网络失败不丢批注。真实调用验证需要配置用户密钥，其他开发不因此停下。

## 第四阶段：跨日、档案分析与长期接续

工作：

- 用户时区内每天一个看板，日内多轮持续更新。零点归档，关闭应用后再打开补做归档。
- 跨零点草稿和任务保留原日期，已完成旧日任务不覆盖新日画面。重试和崩溃恢复不重复写入。
- 档案页接通历史训练、摄入、测量、历日方案、阶段评价和有效认识，不增加第三页。
- 阶段评价使用已有趋势与训练计算，保存来源；用户纠正长期认识后旧摘要失效，下一轮真正采用新认识。
- 完成离线录入、锁屏计时及导出恢复；密钥不进入备份。

通过条件：同日两轮、失败轮次、跨日任务、重启与恢复用例通过；删除或纠正依据后旧摘要不复活；长期资料参与后续看板并保持可追溯。

## 第五阶段：交互、视觉与整体验收

工作：

- 在实际数据与动态卡片上调整Marathon图形语言：中文字体层级、数字编排、颜色、材质与图标，不引入游戏设定。
- 验证长按后点按文字／上划图片、正常纵滚和横滑切页的冲突，提供等效可见入口。批注状态、文本草稿和焦点可恢复。
- 完善统一发送按钮、全体卡片向上离场、结果从下方向上进入、失败返回及减少动效设置。
- 在固定模拟器执行统一规格06的业务和交互验收，记录连续往返与重启／跨日表现；交付APK、构建记录、验证结果和真实缺口。

通过条件：可实际使用的完整往返达到规格；区分源代码检查、自动化测试、模拟器操作和真实API验证，不用任一结果替代其他结果。

## 工作节奏与进展记录

以上是依赖顺序，不是五次用户审批。每次完成一个可验证变化就提交，保持工程可构建；若构建或验收失败，先修复再扩展。同一阶段可先完成一个贯穿领域、数据库和界面的业务切片，避免一次堆完全部表却仍无可用流程。

每阶段完成时更新本文件的状态与证据。测试重点为数值规则、事务、输入保留、去重、跨日和更新传播；视觉与手势以模拟器实际操作验证，不为每个静态样式编写镜像测试。不在没有实现证据时勾选完成。
