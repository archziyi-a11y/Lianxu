# 动态档案与可扩展分析方法验收

日期：2026-10-24。工程：E:/Dev/Android/APP/Lianxu。本轮是第五阶段前的档案功能重构，不表示整套视觉与动效已经完成。

## 已实现的产品行为

档案首页使用六列组件网格，读取持久计算和分析。内容根据当前资料出现；没有合适数据时不生成对应空图、评分或固定六栏目。当前阶段、当前积累及一周／四周／三个月的切换由适用结果决定，不以注册时长直接判断。

长按卡片可优先展示单个信息主题；多主题卡片可分别选择。优先主题跟随新数据、跨日和方法升级更新，不绑定旧卡片或旧结果。归档退出首页，但分类入口和分析历史保留；同一方法／观察对象换时间窗口也不会自动绕回首页。用户重新优先展示可恢复该主题。

首页下方保留身体、训练、营养、阶段、发现分类，以及全部记录、分析历史、历日方案、方法、备份入口。档案没有批注输入、统一发送和收发动效；普通记录编辑、撤销及本地补记继续可用。分类展示独立结果，首页允许AI组合不同主题与时间窗口。

复用既有语义组件，扩展只读图表渲染：真实时间间距的序列、组数／分布条形、训练日历、带单位的分组对比；图形附范围、样本和可访问文字。长训练日历只画最近84天，统计范围另行注明。

## 方法与数据机制

14个内置方法包，12种注册算子。包由manifest.json与guide.md组成，统一管理id、版本、问题、分类、数据口径、适用窗口、门槛、参数和刷新要求。支持测量序列、平滑、训练日历、动作／部位组数分布、可比负重进展、阶段摘要／对比、营养目标沿革、已记录各营养素，以及符合条件时的间隔表现、训练体重和明确饮食场景比较。

最新测量按同日最后一次处理；未知负重不填零，动作比较要求明确器械、负重口径、侧别和相同精确次数。部位映射使用已知规范名／精确动作名，未知动作保留原名，不能用「飞鸟」子串把反向飞鸟误归为胸部。

饮食按既有daily_total、meal覆盖与条目规则逐日去重，部分记录展示已知小计。营养规划与实际摄入分开。场景比较只接受origin.scene的明确值；当前普通输入未提供该字段时，该方法自然不出现，不根据菜名猜测。

关联方法默认至少8个独立日期观测、14天跨度、每组4个样本；比较两个时间半段的方向与效应大小，拒绝只有一个分组、口径不一致或方向不稳定的结果。训练体重方法使用不重叠双周，每周至少3个体重测量日，因此实际需要更长数据积累。以上是可调整的工程筛选，不是因果证据或经过临床验证的阈值。

业务资料仍只有原来的Room事实源。新增archive_methods、archive_topics、archive_placements、archive_presentations、archive_jobs；计算与说明继续存Calculation／Analysis，方法包和用户偏好随备份保存。Room schema5→6只增加表，旧测量迁移测试覆盖1→6；恢复支持本schema6及上一版schema5备份，5版缺少的新表按空表补齐，保留原始事实和附件。

## 外部助手制作流程

档案「分析方法」可复制基于实际注册能力生成的制作提示词；用户与自己的助手讨论后粘贴JSON导入。支持单方法及最多8种方法的集合，整包校验通过后再原子保存；未知算子／字段、非法数值、重复id及不递增版本拒绝，失败保留文本并可复制错误给助手。

用户方法以user.开头，不能覆盖内置方法；可启用／停用。格式及示例见[方法包使用说明](../analysis-methods/README.md)、[制作提示词](../analysis-methods/制作提示词.md)、[JSON格式标准](../analysis-methods/method-package.schema.json)。同一接口既服务内置方法，也服务用户方法；当前不提供可视化编写器或执行任意自定义代码。

## 更新与AI编排

应用级Room观察在事务后合并触发本地计算，独立于档案页是否打开。跨日、重启和恢复时补做检查。结果指纹包含方法版本、资料引用与范围；偏好／布局变化不重新推理，未变化依据沿用已完成分析。

WorkManager使用唯一一次任务合并短期输入，并以持久job状态补做；另有日级后台检查。后台任务不是精确零点定时器。失败有限退避，重新进入前台也检查未完状态，离线保留仍有效的已保存内容。

ArchiveComposer复用deepseek-flash网络适配，只有list_available_results、read_result、run_registered_method、publish_archive四个接口。没有修改训练、摄入、资料或收藏的工具。模型最多5次请求、12次工具，任务180秒；发布检查冻结事实指纹、仍适用的主题、偏好、数值绑定和结果字段，事务应用解释及展示。旧网络返回不能覆盖已更新依据。今日上下文也能读取档案的有效结果。

## 实际边界

没有密钥或网络时，本地方法、数据和图表继续使用；自由解释及AI选取需要云端处理。方法使用可比较记录，不从零散文字凭空估计重量、消耗或身体组成；未达标方法不出现。

旧固定28天assessment保留为历史记录，新首页使用独立方法。当前归档按方法＋观察对象抑制跨窗口重现；优先展示保存所选主题窗口，切换页面的默认窗口也保留其顶部展示。用户另行导入的新方法属于新的分析主题。

后台受Android系统调度限制；真机厂商省电及长期数据规模性能仍需后续设备验证。已验证本地增量、冻结指纹和失败恢复接口，未伪造断网／系统强杀的长周期实机实验。视觉字体、颜色、间距与手势／动效统一仍留第五阶段。

WorkManager版本2.11.2，按[Android官方发布说明](https://developer.android.com/jetpack/androidx/releases/work)核对后加入；任务语义参考[唯一工作管理](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/manage-work)。新增依赖首次合并DEX时768MB堆不足，调到1536MB后构建通过；普通离线构建沿用既有ASCII Gradle缓存目录。
