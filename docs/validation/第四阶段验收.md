# 第四阶段：跨日、档案分析与长期接续

日期：2026-10-24。工程：E:/Dev/Android/APP/Lianxu。默认模型：deepseek-flash。

## 实现范围

保留今日／档案两个横滑页面。档案页内以记录、阶段、历日、资料、备份切换内容，长列表按需绘制，不增加第三个主页面。

- 每个用户时区／日期一个看板。零点切换，重新打开补做归档；原日草稿、冻结输入和在途任务留在原日。归档不改变原任务所依赖的业务版本。旧日任务完成只更新自己的看板；档案中可按原日期重试。
- 历史训练、摄入、测量与长期认识统一读取业务库，可离线补记、修改说明／测量／认识、删除并撤销最近一次修改。撤销生成新版本，不覆盖后续修改。结构化动作和食物细节仍通过「带到看板」批注交给助手整理；「修改说明」只改原文说明。
- 历日入口展示当日餐食方案、未完成补充与处理状态。阶段入口整理近28天训练记录、体重趋势、用户录入体脂与饮食记录覆盖；有依据时提供周均变化，没有数据不虚构身体特征或训练效果。
- 阶段评价、计算和助手长期认识保存依据。更正或删除事实会使相关旧评价失效；已删除事实和失效认识不再进入下一轮上下文。用户纠正的长期认识进入助手当前上下文，旧证据不能自动覆盖纠正。
- 历史记录和阶段摘要可以带到今日看板，成为可继续批注的卡片；重复带入不覆盖尚未发送的补充，干净卡片更新到最新引用。
- 组间计时保存截止时间，使用前台服务与系统通知倒计时，支持熄屏运行和取消。正常同次开机使用单调时钟，避免调整系统时间扰动计时；重新开机恢复时采用保存的时间。通知权限在用户首次开始计时时申请。
- 通过系统文件选择器导出／恢复ZIP，包含业务表、轮次、来源快照、任务、草稿与原始附件。密钥和设置不进入备份；恢复保留本机密钥。附件逐个校验并改写为新的私有路径，数据库整批恢复失败回滚。当前任务或计时运行中不能覆盖恢复；备份中的未完任务转换为可重试失败状态，运行中计时取消。
- Room schema 4→5 非破坏迁移增加 meal_progress、rest_timers，保留原有资料与版本链。

## 日内餐次的修正

记录午餐以后，较早的早餐默认不再纳入「剩余安排」，原方案保留，不新增任何实际摄入。用户可点「仍需安排这餐」重新开放，或主动关闭尚未吃的某餐。实际摄入仍只来自用户记录。

本地候选、卡片操作和AI替换共用此规则。工具返回 closedMealIds／editableMealIds，助手只调整剩余可编辑餐次。第三阶段真实返回曾替换早餐，现保留为必须拒绝的历史回归用例。

真实服务验证同时暴露并修复了两处协议衔接：最终计算推进卡片版本后，仍接受本轮暂存预览中已实际提供给助手的版本；orderedCardIds可指定优先排列的子集，其余卡片按原顺序保留，未知或重复编号仍拒绝，删除只通过removeCardIds。这避免让模型重抄整份无关卡片列表。增加专项回归验证版本、子集排序、无关卡保留和非法编号回滚。

最终APK冷启动成功，身体资料保持空白，计时入口可见；测试没有污染用户身体档案。见[启动检查](stage4-ui-smoke.json)。

## 复现与边界

构建后用 `python scripts/verify-stage3.py --stage 4` 执行模拟器本地回归。显式添加 `--live` 才从忽略的.env读取用户已提供的密钥，以私有临时文件传入并删除；不把密钥放进命令参数、APK或报告。计时实操脚本为 `scripts/verify-stage4-timer.py`。

离线自由文本会忠实保存；自动理解图片、结构化复杂训练和个性化定性分析需要云端服务。阶段本地摘要仅描述已有数据，尚不承诺体脂设备准确性或从训练记录直接测出肌肉增长。

备份当前只接受相同schema版本，数据JSON最大16MB，单附件25MB、总解压256MB；不是跨版本升级迁移工具。恢复会替换本机业务库，界面在用户选定文件后明确确认覆盖。

本阶段验证在既定模拟器完成。真机后台限制、厂商省电及重启后计时的设备行为尚未实测，不能用单调时钟单元用例替代这些验证。视觉编排、手势冲突、全体收发与减少动效的统一打磨留在第五阶段。

Android实现依据：[系统文件选择](https://developer.android.com/training/data-storage/shared/documents-files)、[specialUse前台服务](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use)、[系统倒计时通知](https://developer.android.com/reference/android/app/Notification.Builder#setChronometerCountDown(boolean))。
