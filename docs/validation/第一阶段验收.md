# 第一阶段：共享数据与恢复能力

日期：2026-10-24。范围：接手开发计划的第一阶段。真实DeepSeek调用未执行。

## 已实现

- Room升级为版本2，保留原有9张表，新增10张持久表；导出版本1、2的schema，采用1→2非破坏迁移。
- 接通训练、摄入、认识的记录访问，以及草稿、附件、输入、任务、轮次、看板、快照、计算、分析、规划、策略与提交凭据的存取接口。
- 档案更新和目标切换在同一事务执行；新目标结束旧阶段，并修复旧数据中多项未结束目标。未知体重不填零，缺少公式参数不猜测。已保存资料经共享Repository流进入档案页和今日页摘要。
- 卡片批注与编辑状态存入草稿；图片复制至应用私有目录，保存大小、SHA-256与附件ID，不长期依赖系统选择器URI。
- 提交冻结原话、卡片标识、版本与内容快照。结果、前后看板快照、成功轮次与凭据共同提交。失败保留输入，同稿重试沿用轮次，重复应用返回已有结果；处理期间的新稿不被旧提交清除。
- 冷启动恢复中断任务为可重试状态；按日期／时区区分看板标识，卡片标识不会跨日覆盖。完整零点归档仍属于第四阶段。
- 用Android Keystore管理加密密钥，AES-GCM保护API凭据；读取时迁移旧明文，备份／设备转移排除设置文件，取消请求体日志。设置输入框遮挡密钥。
- 移除随机健康指标和随机演示改数，改为明确的本地输入占位与演示提示；失败原因可见，原始补充保留。
- 将已有动态依赖固定为实际使用的Adaptive 1.3.0与Lifecycle Navigation3 2.11.0，未进行技术栈升级。

工具链：Windows、Android Studio随附JBR 25.0.3、Gradle 9.6.0、AGP 9.4.1、compile／target SDK 37、min SDK 26。模拟器：emulator-5554，Android 17／API 37。

- `:app:assembleDebug`：通过；最终界面修正后再次构建通过，并安装运行。
- `:app:testDebugUnitTest`：通过。目前仍是原有1项模板测试，不作为业务覆盖证明。
- `:app:assembleDebugAndroidTest`：通过。
- AndroidJUnitRunner在模拟器执行10项测试全部通过：9项新增测试涵盖旧库升级保留体重、目标／未知值、粗略训练与摄入重开恢复、图片与草稿恢复、同轮重试和重复提交、存储中途异常回滚与新稿保留、中断恢复、跨日卡片隔离、凭据迁移与清除；另有1项原有包名测试。
- 实际界面操作：冷启动→长按训练卡→输入并保存测试批注→强制停止应用→新进程打开→原卡单点重开输入框→原文准确恢复。已移除临时测试文字。演示标识可见。
- 静态检查：原有9表schema保持不变；备份XML可解析；git diff空白检查通过。

## 测试环境处理

初次单元测试失败于含中文的Gradle工作路径；采用本地ASCII目录`E:/Dev/Android/gradle-test-home`并链接既有依赖缓存。工作站同时运行Studio与模拟器时又遇到内存不足，停止空闲Gradle守护进程后，将验证构建限制为单worker、Gradle堆768MB、测试堆192MB，随后单元测试通过。

Gradle的connectedDebugAndroidTest未运行成功，原因是离线缓存缺少UTP gradle-work-action 32.4.1。没有将该任务宣称为通过；实际安装测试APK并直接执行AndroidJUnitRunner，结果为OK (10 tests)。


## 阶段边界

当前卡片仍使用过渡的文字渲染缓存；业务引用型组件、真实营养与食物配方规划在第二阶段实现。新增业务表已具备存取接口，不等于其业务功能已完成。用户补充已作为原始输入持久保存，自动提取为训练／摄入事实及正式工具事务属于第三阶段。

暂保留旧文本服务适配入口供替换，不声称实现了完整助手协议。真实模式遇到图片会明确保留输入并报告视觉请求尚未接通，不默默只发文字。正式视觉、多轮工具、长期认识传播、跨日归档与完整备份导出仍按后续阶段完成。

实现依据参考：[Room迁移](https://developer.android.com/training/data-storage/room/migrating-db-versions)、[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[系统备份规则](https://developer.android.com/identity/data/autobackup)。
