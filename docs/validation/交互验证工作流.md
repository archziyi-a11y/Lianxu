# 练序交互验证工作流

目标：将可重复的设备操作、版本核对、录屏定位自动化，再集中审阅一批问题。
此流程验证真实界面操作与动画；固定离线回复不代表真实 AI 分析。

## 隔离与构建

- `evidence` 构建变体使用 `com.example.lianxu.evidence`，与已有应用分开安装。
- `EvidenceActivity` 使用内存 Room、独立 Application 和固定 AgentClient；复用正式 MainScreen、ViewModel、主题、持久化协议。
- 六条历史训练是隔离种子；两张文字批注不得新增虚构训练实绩。
- 使用 Android 正常帧时钟，不再由 instrumentation 手动推进动画。
- 原 `deliverables/Lianxu-stage5-debug.apk` 与第五阶段证据保留。

在仓库根目录使用 PowerShell：

```powershell
$env:JAVA_HOME='E:/Program Files/Android/Android Studio/jbr'
$env:GRADLE_USER_HOME='E:/Dev/Android/gradle-test-home'
./gradlew.bat :app:assembleEvidence --offline --no-configuration-cache --max-workers=1 '-Dorg.gradle.jvmargs=-Xmx1536m -Dfile.encoding=UTF-8'
./gradlew.bat --stop
python scripts/workflow/install-maestro.py
python scripts/verify-workflow.py --driver maestro
python scripts/verify-workflow.py --driver adb
```

设备需已启动，默认 `emulator-5554`；可用 `--serial` 指定。此基线检查 1080×2400，ADB 滑动坐标针对该尺寸；其他尺寸应另建场景。
编译后停止该 Gradle 用户目录下的构建守护进程，再做设备对照。本轮曾在主机可用内存不足 1GB 时连续超时，停止守护进程后可用内存约 3.5GB，原 20 秒回复限制内通过；不要通过放宽断言时限掩盖这种环境变化。
Maestro 固定 2.11.0，安装脚本校验官方 release SHA-256。仅使用本地测试，禁用匿名统计，不使用云录屏、云分析。

## 每次运行与审阅

每次运行使用唯一编号，保存在 `docs/validation/workflow-runs/`。失败与成功都保留，不覆盖旧文件。

1. 安装独立包，清除旧 Activity 任务并等待启动；检查与本轮编号匹配的 ready 标记、今日文字、截图尺寸。
2. 在卧推、接续上次卡片分别长按、点按输入、收好，检查两张待发送，统一发送。
3. 检查回复真实可见、仅一条完成轮次、两条输入原文完整、训练数仍为六。
4. 保存 APK/源文件/流程摘要、设备信息、动作时间、业务事件、数据库结果、完整录屏、关键截图和 Maestro 逐步报告。
5. 将多次成功运行一起交给审阅脚本：

```powershell
python scripts/workflow/review-evidence.py <运行编号1> <运行编号2>
```

生成本地 HTML：自动定位收发短片，提供原速/半速/逐帧按钮、连续帧图、原录屏、版本和断言结果。
FFmpeg 优先使用 `LIANXU_FFMPEG`；否则沿用 `app/build/stage5-media-tools` 的 imageio-ffmpeg。
短片按业务事件与录屏启动时间近似对齐，保留前后余量；不能把这些时间当成精确的动画或响应延迟基准。
先完整审阅所有成功运行、集中列问题，再成批修复并生成新证据。最终状态断言不能替代转场审阅。

原始运行默认被 Git 忽略，仅将验收选中的证据显式加入提交。manifest 中保存原始文件摘要。
HTML 使用相对路径，可离线打开。逐帧按钮按导出视频的 30fps 跳转，浏览器实际定位精度仍受解码器影响。

## MCP

```powershell
python scripts/workflow/probe-mcp.py
# 在上述成功运行仍显示回复时，额外读取界面并执行可见性断言：
python scripts/workflow/probe-mcp.py --assert-reply
```

Maestro 2.11.0 的实际 MCP 工具包括 `list_devices`、`inspect_screen`、`take_screenshot`、`run`、`cheat_sheet`。
与早期文档工具名称不同，应以 `tools/list` 为准。
本地 stdio 探针不改全局 Codex 配置；它验证服务能力，不表示当前聊天已自动获得原生 MCP 工具。
后续客户端连接命令为 `app/build/workflow-tools/maestro/bin/maestro.bat mcp --no-viewer --working-dir <仓库绝对路径>`，环境沿用脚本中的 JBR、SDK 与禁用统计设置。

## 评估边界

- 同一安装包、同一隔离种子、同一两卡场景内比较耗时；不同版本不得直接合并统计。
- 两种驱动的长按时长、等待策略不同，耗时记录只反映该流程的运行成本，不是严格的驱动性能基准。
- `hostAdbCalls` 只统计包装脚本调用，未统计 Maestro 内部操作，不能将其当成总工具调用数。
- 少量成功重复只能证明当前模拟器可复现，不能宣称跨设备稳定性或统计显著加速。
- 模型能读取截图与连续帧；此工具链没有赋予模型连续视觉感知。交互意图、动效质量仍需审阅判断。
