## 实现与边界

正式主题采用纸白／石墨、酸黄主操作和蓝绿信息面；中文系统无衬线回退、condensed 数字。六列混合网格、横滑两页、点／线插值指示保持。窄屏／大字体整行卡片，横屏收紧页头；系统栏和键盘安全区跟随主题。

长按卡片在原处激活，点按提示区进入文字，上划提示区切换图片入口，再打开系统相册。提示区捕获上划，普通卡片仍正常纵滚；文字/图片按钮为等效入口。组数滑块使用自身横向手势，多卡补充统一提交。全网格向上退出260ms、从下向上进入420ms，处理慢时有进度与停止入口。默认回复置于新看板前部。

控件、批注和附件冻结为同轮 InputBundle。明确控件值先在隔离暂存库建立事实，经同一来源检查和事务进入正式库；重复提交不重复入账。空白、候选动作名和图片材料不会自动成为完成实绩。无网络可保存本地明确数据、粗略原文与附件，不声称得到新 AI 推理。

输入习惯、跟进安排、进展及方法邀请复用版本化 KnowledgeNote；现有导出恢复携带这些记录。取消墓碑进入上下文和事务指纹，旧请求不能覆盖取消。取消历史存在时，新的持续安排须在档案明确新建或重新开启；其他有效安排继续。此保守规则避免用相似文本推断用户意愿。

方法邀请首轮覆盖与目标有关、补一次测量即可满足原门槛的注册体重 series/rolling_mean 方法，每次最多一项。缺少可比口径不转成问卷；略过按方法版本及证据记忆；假想测量只用于内存中的适用性检查，绝不持久化或展示为结果。

## 实际模拟器操作

设备：Medium_Phone_API_37.0 / emulator-5554，API37；正常1080×2400、420dpi。通过 ADB 注入系统触摸和按键，真实打开系统照片选择器；没有以直接调用 ViewModel 冒充这些手势。

`verify-stage5-gestures.py` 在隔离测试会话内连续操作：长按卧推 → 原处键入且逐字校验 → 候选动作和实际滑块 → 另一张卡长按上划 → 系统相册选图 → 两卡统一发送 → 回复后第二轮补充 → 横滑档案 → 取消跟进。受控回复明确写明隔离样本，不代替上述真实 API 证据。原始录屏、动作时间线和数据结果位于 `stage5-device/`。

实际发现并修正：

1. 文字直接等数据库回读会丢快速输入；改为 TextFieldState 即时处理输入，后台顺序保存。控件也即时回显。随后系统按键注入的完整字符串通过相等校验。
2. 键盘使底部完成按钮离开可视区；移至输入框内，并主动收起键盘。消费外层安全区、收紧编辑页头、将输入框滚入可视区后，320dp宽、1.35倍字体仍能输入和完成。
3. 新建卡片及默认回复容易埋在长页面下方；创建后定位新卡，提交后回到新看板顶部。
4. 小屏日期曾换成两行数字；窄屏独立显示日期。横屏保留操作和滚动，缩短大页头。
5. 营养目标原先沿用“最近记录”标签；改为“当前目标”，今日数值卡标题明确包含“目标”，与实际摄入分开。
6. 丰富看板的回复可能晚于处理标志到达，列表仍锚定旧首卡；改为也监听新首卡身份回到顶部，新增无主动滚动的回复可见性回归并通过。

## 复现

先按交接命令构建，随后：

```powershell
python scripts/verify-stage3.py --stage 5 --label stage5-final
python scripts/verify-stage3.py --stage 5 --class-name com.example.lianxu.StageFiveLiveTest --label stage5-active-live --live
python scripts/stage5-device.py start
python scripts/verify-stage5-gestures.py
python scripts/stage5-device.py stop
```
