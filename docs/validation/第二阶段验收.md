# 第二阶段：营养计算、餐食与引用型看板

日期：2026-10-24。范围：接手开发计划第二阶段。默认模型按用户指定改为`deepseek-flash`；本阶段没有发起真实模型调用，没有将.env中的密钥打包进应用。

## 已实现的行为

- 按明确计算日期生成营养目标，使用该日期之前的最新体重，保存完整精度、输入快照、来源版本和方法版本。展示舍入不影响计算，缺失字段和超出公式范围返回明确状态。
- 支持能量、蛋白、碳水、脂肪及可选纤维的手动目标；保留与4/4/9换算的差额，不擅自校正。档案页和今日页通过同一持久计算服务取得结果。
- 应用内置31项真实食物及36个场景配方条目，原始文件字节与来源manifest一致，运行时核对SHA-256。36个条目是12种组合在三个场景下的版本，不是36种独立菜式。
- 食物按100g基础换算，保留生熟状态、来源和未知营养项；没有份量映射时不凭空把“一碗”换成固定克数。摄入总量与明细按指标去重，缺项不填零。
- 采用有界、可重复的餐食搜索和5g实际份量步长，优先满足禁食与场景条件。提供单餐替换、配方份量档位、逐餐场景选择、保留／解锁及“记为已吃”。局部修改保留其他餐，已吃内容保存为独立快照，重复点击不重复记入。
- 卡片可组合文本、指标、清单、选择、趋势与图片组件。业务指标引用不可变Calculation；建议文字引用Analysis；食物清单引用规划版本。界面解析引用，不另存一套可独立修改的营养数字。
- 数据不足时只显示可用信息和补充入口；没有体重或训练记录时不填空曲线。已有体重显示日均点位，只有两段各足够测量日时才报告周变化；训练摘要保留区间与已知负重口径。
- 更正资料触发当前规划重算，旧计算继续保留。Profile与规划版本进入不可变快照表。批注目标的标题、可读原文、组件结构和当时版本在首次批改时锚定，自动刷新保留待发批注及原锚点。
- 无AI密钥时，本地营养和餐食功能仍是正式能力。自由批注的完整AI协作尚未接通，界面不将本地规划标成虚构AI回复。

## 运行与测试证据

环境沿用第一阶段：JBR 25.0.3、Gradle 9.6.0、AGP 9.4.1；模拟器emulator-5554，Android 17／API 37。

- `:app:assembleDebug`、`:app:testDebugUnitTest`、`:app:assembleDebugAndroidTest`均通过，最新APK已安装到模拟器。
- 16项新增计算规则测试通过，覆盖公式精确值、显示舍入、缺项、日期、适用范围、手动目标、食物换算、空营养项、防双计、确定性搜索、单餐替换、限制、训练摘要及体重趋势。另有1项原有模板单元测试，不作为业务覆盖依据。
- 18项AndroidJUnitRunner测试通过，其中新增7项业务集成与1项实际组件点击测试，其余10项为第一阶段回归与原有包名测试。
- 集成测试验证了：缺资料无假指标、手动目标无需填写整套身体资料、资产加载、计算引用、刷新幂等、单餐替换／份量／场景、旧规划快照、重复记为已吃、后续重算不改摄入、更正体重不丢原批注锚点、未来体重排除、重开同一规划、描述摄入不显示伪造零值。
- Compose界面测试在隔离测试库上点击真实餐食卡的“记为已吃”，验证按钮消失、卡片变为已记录、数据库新增一条摄入。测试未向个人档案写入虚构资料。
- 应用实际冷启动显示缺资料状态，左右滑动进入档案并返回今日成功；未触发真实API请求。
- 数据库升至版本3，新增entity_snapshots一表；原有19表保持不变，1→2→3迁移测试保留旧测量记录。

## 遇到并解决的问题

原Espresso 3.5.1在当前模拟器上因InputManager.getInstance反射接口失效而无法启动界面交互测试。按照[AndroidX Test官方发布说明](https://developer.android.com/jetpack/androidx/releases/test#espresso-3.7.0)升级测试依赖至Espresso 3.7.0及ext.junit 1.3.0，随后界面测试通过。没有以跳过失败测试代替修复。

验证仍采用第一阶段记录的ASCII Gradle用户目录和单worker设置。模拟器测试通过安装测试APK后直接运行AndroidJUnitRunner执行；未声称Gradle connectedDebugAndroidTest已通过。

## 阶段边界

本阶段交付确定性的初始营养看板、真实数据计算、组件渲染和本地操作。第三阶段才接通完整多卡意图理解、多模态请求、查询／计算工具循环及AI组织组件回复；目前保留的旧文本适配器不等于正式工具协议。餐食份量按钮使用配方已定义档位，自由批改中的任意食物增补／改克数仍需后续AI与工具流程处理。

零点归档、阶段性认识传播、长期档案完整浏览、导出恢复和锁屏计时仍按第四阶段推进；视觉与手感的整体验收仍属第五阶段。此处不将第二阶段完成等同于完整首版完成。
