# 练序：美术与动效参考（第一轮）

整理日期：2026-10-24。

用途：为第五阶段建立可讨论的参考范围。以下迁移建议属于设计提案，尚未成为最终视觉规格；本轮不修改应用界面。

## 已确认的方向

- 参考 Bungie《Marathon》的图形写实主义，重点是菜单、字体、数据编排、颜色与图形系统。只迁移美术语言。
- 产品气质为冷静、精准的训练仪器；醒目的视觉个性可以与节制的信息展示并存。
- 今日与档案为左右滑动的两页，底部点／短横线指示位置，不增加导航栏。
- 今日以六列隐形网格组织可组合卡片；长按进入批注，点按文字、上划图片，底部矩形箭头批量提交。
- 所有当前卡片向上离场，回复卡片从下方向上进入。发送不是归档；一天可以多轮更新。
- 档案保留稳定主题与入口，有依据才展示，允许优先展示／归档，不加入批注发送流程。

## 优先观看的资料

### 1. KARAKTER — Marathon / Graphic Realism

原始设计团队作品页：[Marathon](https://karakter.de/marathon_new/)。重点定位到页面后半段 **GRAPHIC REALISM**。

内容：该工作室的 Marathon 项目设计与图形写实主义作品。它是世界及概念设计参考，不是完整的手机界面规范。

迁移建议：研究大块面、几何轮廓与图形标识如何形成统一系统。用于卡片轮廓、内容分区、强调区域与少量材质；在信息界面中以平整表面为主，让文字和数字承担主要表达。

讨论问题：我们希望卡片更像精确切分的面板，还是像独立放置的标签？这会影响边界、间距和背景的关系。

### 2. Marathon 官方网站

官方展示：[Marathon Homepage](https://marathonthegame.com/)。建议在桌面与手机宽度分别查看。

内容：品牌在真实网页上的应用，可现场观察字号、图形、色块和内容尺度的关系。网站内容会更新，本清单未固定其某个历史版本。

迁移建议：提取标题、主数字、单位、辅助说明之间的层级；在六列网格中建立明确对齐线。中文标题与段落需要重新设计，不能直接套用英文大写排版。

讨论问题：荧光色主要标识可操作内容、当前重点，还是用作大块背景？建议先比较“小面积强调”和“少量整块强调”两个版本。

### 3. Bungie Marathon Art Blast

原始团队作品汇编：[ArtStation Magazine](https://magazine.artstation.com/2026/06/bungie-marathon-art-blast/)。

内容：2026 年 6 月发布的团队作品入口，包含角色、概念、世界、特效等多个方向及作者链接。适合核对整体艺术语言，不能把整篇当成 UI 案例。

迁移建议：用于保持配色、形状和图形细节的一致性。筛选时优先找平面图形、标识与可读信息层级；角色、场景与游戏叙事不进入健身界面。

### 4. Victory Over All — Marathon Fanart Posters

作者作品：[Marathon Fanart Posters](https://www.victoryoverall.co.uk/work/marathon-fanart)。明确为独立创作的同人海报，非官方 UI。

内容：作者说明其修改了自有 Basilisk 字体来制作排版，并创作人物插图。

迁移建议：把它当作标题与图形编排的探索材料，讨论数字的视觉重量、字宽、疏密和色块比例。海报层级只能用于局部主视觉，正文、数据表和连续阅读要另行制定规则。

## 动效与操作参考

### 5. Quint Blanche — Exodus-12

作者作品与嵌入视频：[Exodus-12 — Sci-fi FUI Animation](https://quintblanche.artstation.com/projects/w09eLg)。

作者明确说明作品受 Bungie Marathon 启发，以 After Effects 制作，并与音乐节奏同步。这是虚构界面的叙事动画，不是已经验证的触屏交互。

观看重点：作为图形界面动效的节奏候选，讨论面板、文字和信息如何依次出现。是否采用具体处理，需要实际观看视频后逐段确定。本轮已核对作者说明和视频入口，未对视频做逐帧审阅。

迁移建议：可为发送与返回的短暂集中动效提供灵感。实际操作的时长应由用户动作与处理状态决定，不随音乐编排，也不增加持续循环的装饰运动。

### 6. Google Material — Choreography

官方动态图例：[Choreography](https://m1.material.io/motion/choreography.html)。这是旧版 Material 资料，用来研究空间连续性，不作为当前 Android API 或整套视觉风格的依据。

内容：保留转场焦点、让新表面与触发位置关联、多元素协同进入等原则及示例。

迁移建议：批注输入在被操作卡片附近建立来源感；用户始终认得刚才操作的卡片。批量发送保持整组方向一致，返回时维持清晰的阅读顺序。可以试验很小的错峰，不让一页卡片逐张表演延长等待。

### 7. Android Developers — Compose 动画示例

官方可视化示例：[Quick guide to Animations](https://developer.android.com/develop/ui/compose/animation/quick-guide)。

内容：出现／消失、颜色、大小、位置和内容变化等动画案例。

迁移建议：分别制作按压反馈、批注边界变化、输入区域展开、档案优先展示后的布局移动样例。每个变化对应明确的交互状态，避免把同一种动画套在全部操作上。

### 8. Android Developers — 手势与动画连续性

官方实现说明：[Advanced animation example: Gestures](https://developer.android.com/develop/ui/compose/animation/advanced)。

内容：手势开始时中断动画，拖动过程中同步位置，松手后以速度和目标位置继续运动。

迁移建议：两页切换跟手；底部点／线随页面进度变化。卡片处于允许操作的状态时，用户重新触碰不必等待装饰动画结束。档案卡片位置变化应保留主题身份。

## 对练序的第一轮转译提案

以下是我们自己的设计判断，参考资料并没有替我们确定这些方案。

### 静态视觉

1. 字体与网格作为主骨架：标题有力度，数字与单位有精确层级，正文保持舒适阅读。中文、英文、数字一起做样张再选字体。
2. 基础表面与强调色分工明确：可比较深色／近白混合面板及单一主强调色的方案，不把“黑底荧光边框”当作风格的全部。
3. 材质优先通过平整色面、细分隔、局部纹理体现；小字、图表刻度和主数字保持干净。
4. 图标保持统一轮廓和笔画。图表先讲清单位、时间、比较口径；不用无数据含义的装饰刻度填空。
5. 今日更强调可操作状态和本轮重点；档案更强调信息主题、时间范围与阅读秩序，两页共用字体、颜色和组件语言。

### 动效场景

- 长按：卡片局部反馈，边界或主题色转入批注态，必要时配合短促触觉反馈。
- 输入：点按后出现文字输入；上划后出现图片入口。补充内容的归属保持可见。
- 发送：整组向上离场；等待有明确反馈；结果从下方接续进入。网络耗时不由动画假装固定。
- 失败：输入和旧内容仍可恢复，位置与反馈要让用户看懂发生了什么。
- 切页：直接跟手，指示器的点到短线变化与滑动进度关联。
- 优先展示／归档：只编排有关卡片与其邻居的移动，保持主题可追踪。
- 增量更新：刷新实际变化的数字、图表和文字，避免每天打开档案都重新入场或随机改换顺序。
- 减少动效：保留状态反馈，以简短过渡代替大幅空间移动。

不在此时确定统一毫秒数、弹簧参数、字体家族或最终色值。这些需要放到真实中文内容和现有组件上比较。

## 建议的比较方式

先看 KARAKTER、官网、Exodus-12 三个入口，分别讨论形状、信息层级与节奏。随后用同一份真实内容制作两个静态方向：一版偏严格仪器排版，一版偏大胆图形编排；再在选定方向上验证长按批注、整组收发、档案优先展示三个连续动效。

验收重点：内容是否一眼有主次；用户能否辨认批注归属；发送和回复的方向是否符合既定约定；重复使用是否仍利落；档案更新后是否仍找得到原来关注的信息。
