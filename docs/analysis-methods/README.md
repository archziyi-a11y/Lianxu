# 制作自己的分析方法

在档案底部进入「分析方法」，点击「复制制作提示词」，交给自己的聊天助手。讨论清楚要观察的问题后，让助手生成完整方法包JSON，再回应用「粘贴导入方法包」。应用提示具体错误时，将错误发给助手修正，输入会保留。

单包格式为schemaVersion、manifest和guide；也可一次导入最多8种方法的packages集合。不同方法独立运行，档案助手可组合它们的结果。id以user.开头；修改同id的方法必须递增version。内置方法不能被用户包覆盖。启用／停用入口与导入入口位于同一页，方法及状态随备份保存。

[完整示例](方法包示例.json)、[格式标准](method-package.schema.json)。制作提示词从应用实际注册的算子与内置示例生成，[导出副本](制作提示词.md)用于在应用外复制。不同应用版本应使用其对应提示词。

现有方法覆盖测量序列与平滑、训练日历、已知组数分布、同口径动作进展、阶段摘要／对比、营养规划、已记录饮食，以及达到条件后的间隔表现／训练体重／明确饮食场景比较。算子内部的口径和检查不能靠描述绕过。

关系比较的工程默认：至少8个独立日期观测、14天覆盖、每组至少4个样本，并要求两个时间段的差异方向一致。训练体重采用不重叠双周，需更长数据覆盖；平滑趋势要求相邻窗口各至少3个测量日。它们属于可复核的观察方法，不是因果证明。

scene_compare仅使用IntakeEntry.origin.scene的明确场景值，当前普通饮食输入未提供此字段时不会出现该分析；不根据食物名称猜测场景。未知重量、未记录摄入不补零。方法包能执行不等于其统计设想已被科学验证，guide应说明适用范围与反例。
